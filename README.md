# The Packetfather

Open-source Wi-Fi driver and packet stack for ESP32.

The Packetfather is an attempt to build a programmable Wi-Fi stack for ESP32 where the developer has full control over packets instead of only using the high-level networking behavior exposed by the official stack.


I want an ESP32 environment where I can inspect, build, modify, route, inject, receive, and reason about packets with the same kind of freedom that tools like Scapy give on a computer, but running directly on the microcontroller.

## Goal

The goal is to create a driver and packet-control stack that gives full control over Wi-Fi traffic on ESP32:

- packets before joining a network;
- packets after joining a network;
- packets generated by the ESP32 itself;
- packets received from the air;
- packets that are accepted, filtered, modified, replied to, or forwarded;
- raw 802.11 frames;
- higher-level network frames as the project grows.

In short: **a Scapy-like packet stack for ESP32**, backed by a real open Wi-Fi driver.

## Why This Exists

ESP32 is powerful, cheap, and everywhere. It is one of the best platforms for learning embedded networking and building wireless tools.

But the default Wi-Fi stack is not designed for complete packet ownership. It is designed to connect, send normal traffic, receive normal traffic, and hide most of the Wi-Fi internals.

That is great for products.

It is not enough if you want to build your own packet stack.

The Packetfather exists because I want to control the whole path:

- frame construction;
- frame parsing;
- RX and TX behavior;
- filtering;
- MAC-layer decisions;
- packet metadata;
- packet mutation;
- custom protocol experiments;
- traffic inside a network;
- traffic outside association;
- eventually, higher-level packet tooling on top of the driver.

## Vision

The long-term vision is an ESP32 packet framework where code can do things like:

- receive raw Wi-Fi frames;
- parse 802.11 headers into structured objects;
- build custom management, control, and data frames;
- define packet filters in firmware;
- modify packets before responding;
- craft replies;
- control when and how packets are transmitted;
- expose simple APIs for packet experiments;
- bridge low-level Wi-Fi frames into higher-level protocol tooling.

The final shape should feel closer to a packet laboratory than a normal network example.

## Project Status

Current maturity: **early experimental prototype**.

The project is not yet a complete Wi-Fi driver or a finished Scapy-like packet API. Right now it is the first driver-layer foundation needed to make that packet stack possible.

## Architecture Direction

The project is expected to grow in layers:

```text
packet tooling / Scapy-like API
        |
packet builders, parsers, filters, mutators
        |
open MAC / packet control layer
        |
ESP32 Wi-Fi driver
        |
DMA, registers, PHY/RF initialization
        |
ESP32 hardware
```

The low-level pieces exist so the upper packet-control layers can eventually be real, not just wrappers around the official Wi-Fi API.

## Roadmap

Short-term:

- stabilize RX DMA behavior;
- collect reproducible raw packet buffers;
- improve the 802.11 parser;
- document register behavior;
- define a first internal packet representation;
- separate research probes from driver code.

Medium-term:

- build packet objects inspired by Scapy;
- add frame builders for common 802.11 packet types;
- expose RX callbacks;
- add programmable filters;
- experiment with controlled TX;
- begin shaping a clean driver API.

Long-term:

- full packet crafting from ESP32 firmware;
- custom MAC behavior;
- packet mutation and reply logic;
- higher-level protocol helpers;
- integration paths for normal network use when desired;
- support for more ESP32 variants if the hardware mapping allows it.

## Build

Install ESP-IDF, activate its environment, then build for ESP32-C3:

```powershell
idf.py set-target esp32c3
idf.py build
```

You can also use the helper `Makefile`:

```powershell
make build
make flash PORT=COMx
make monitor PORT=COMx
```

Replace `COMx` with your board's serial port.
